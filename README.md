# dragonwilds-dedicated-server-docker

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

A minimal, fully auditable Docker build for a self-hosted **RuneScape: Dragonwilds**
dedicated server (Steam app ID `4019830`), built for Linux hosts and tested with
Nintendo Switch 2 / crossplay clients.

This isn't a fork of an existing image - it's a from-scratch `debian:bookworm-slim`
build with 32-bit SteamCMD compat libs, running as a non-root user. It exists
because a few real bugs in the SteamCMD/Dragonwilds install path aren't
documented anywhere else right now (see **Known issues** below), and a
from-scratch Dockerfile is just easier to trust than an opaque pre-built
image for something sitting on your home network.

## Two variants - pick one

| | `manual-update/` | `auto-update/` |
|---|---|---|
| Checks for game updates on every start | No | Yes |
| Update trigger | You run it explicitly | Automatic |
| Best for | Switch/console players using the join-code workaround (see below) | PC players who don't rely on a stable join code |

**Why this matters:** every server restart regenerates the session's
`JoinCode`. If your only reliable way to connect is the join-code workaround
(common on Switch 2 right now - see below), an auto-updating server that
restarts itself on a schedule will silently strand you with a stale code.
`manual-update` never restarts itself; you control exactly when the code
changes.

## Requirements

- Docker + Docker Compose v2
- A Linux host (built/tested on Debian bookworm-slim inside the container; any recent Docker host works)
- ~5-10GB free disk for the SteamCMD install
- Ability to forward a UDP port from your router to the host

## Quick start

```bash
git clone <this-repo-url>
cd dragonwilds-dedicated-server-docker/manual-update   # or auto-update/
docker compose up -d --build
docker compose logs -f
```

First start does a full SteamCMD install (a few GB, can take a while).
Subsequent starts on `manual-update` skip straight to launch; on
`auto-update` they re-check with SteamCMD first.

To trigger a manual update at any time (works with either variant):

```bash
docker compose stop dragonwilds
docker compose run --rm dragonwilds update
docker compose up -d
```

## Finding your join code

If your client can't search for the server by name (see the Switch keyboard
bug below), Dragonwilds dedicated servers log a session join code on startup:

```bash
docker compose logs dragonwilds | grep -i joincode
```

Enter that code in your client's "join by code" option instead of searching
by name. Re-run this after any restart/update - the code changes each time
the server session restarts.

## Configuration

The dedicated server only reads one config file, generated on first run at
`RSDragonwilds/Saved/Config/LinuxServer/DedicatedServer.ini` inside the
volume. This is the **complete, ground-truth key list** - confirmed by
reading the actual generated file, not third-party doc summaries (several of
which incorrectly list `AdminPassword` as a required key - it doesn't exist):

```ini
[/Script/Dominion.DedicatedServerSettings]
OwnerId=<player ID from your platform's Settings menu>
ServerGuid=<auto-generated, don't touch>
ServerName=<your server name>
WorldPassword=<optional, blank = no password>
DefaultWorldName=<world name, max 16 chars, case-sensitive in search>
PlatformPolicy=Crossplay
bAllowSendingCrashDumps=False
```

There is genuinely nothing else to configure server-side in this build - no
difficulty, PvP, XP-rate, or day/night settings exist. `GameUserSettings.ini`
and `Engine.ini` (also auto-generated) are purely client-side
rendering/accessibility and engine content-mount settings respectively -
irrelevant to gameplay.

**World type (Standard/Custom/Creative):** this is *not* a config file
setting. It's chosen when the world is first created - either in a PC/Steam
client (with the resulting `.sav` copied onto the server) or, if left to
auto-generate as this build does, it defaults to **Standard**. If you're
Switch-only with no Steam install, you're stuck with Standard unless someone
exports a world for you.

## Networking

Both compose files default to `network_mode: host`. This was required on the
host this was built and tested on - Docker's default bridge networking broke
SteamCMD's anonymous-login handshake outright (confirmed via host-vs-container
isolation testing; an IPv6-disable workaround did *not* fix it).

**Caveat:** a few other community Dragonwilds docker images run fine on
ordinary bridge networking with a mapped port. It's possible the bridge
failure here was specific to this host's network stack (firewalld + Docker's
interaction with it) rather than a universal SteamCMD/Dragonwilds issue. If
you want to keep isolation, try bridge mode first:

```yaml
# remove network_mode: host, add:
ports:
  - "7777:7777/udp"
```

and only fall back to host networking if the SteamCMD install step fails
with an anonymous-login/handshake error. Host networking has a real
trade-off: the container shares your host's entire network stack, no NAT
isolation.

Either way, you'll also need:
- Router: UDP port 7777 forwarded to your server's LAN IP (a DHCP
  reservation for that IP is strongly recommended, otherwise the forward can
  silently point at the wrong device after a lease change)
- Host firewall: allow UDP 7777 (e.g. `firewalld`: `firewall-cmd
  --add-port=7777/udp --permanent && firewall-cmd --reload`)

## Switch 2 connectivity notes

- The in-game server-name search field's on-screen keyboard doesn't appear
  on Switch 2 (confirmed on the 1.0 build) - you can't type a search query.
  Use the join-code option instead (see above).
- If you're playing over a cloud-streaming client (e.g. GeForce Now), it
  reaches your server over the public internet like any remote player,
  regardless of being on the same Wi-Fi network as your server. Treat it as
  "open this to the internet properly," not a LAN problem.
- Steam invites to a dedicated server don't currently work as intended -
  this is a known limitation from Jagex, not specific to this build.

## Known issues fixed by this build

1. **SteamCMD appinfo-cache race on `app_update`.** A fresh install can fail
   with `Missing configuration` on this app ID. Fix (baked into
   `entrypoint.sh`): run `+app_info_update 1 +app_info_print 4019830` before
   `+app_update`. Same class of issue as
   [mbround18/valheim-docker#1508](https://github.com/mbround18/valheim-docker/pull/1508).
2. **Missing `libcurl.so.4`.** The bundled Sentry/crashpad crash-reporter
   fails to load without it. Fixed by installing `libcurl4` in the
   Dockerfile.
3. **False "multiple instances of the game detected" shutdown.** Usually a
   genuinely orphaned server process still bound to UDP 7777 from an earlier
   run, not a bug. Find it with `sudo ss -tulnp | sort` and kill it. This
   image runs with Docker's `init: true` so orphaned child processes get
   cleaned up instead of piling up.

## Still open / not handled by this repo

- Auto-restart on container/host reboot uses `restart: unless-stopped` -
  make sure your Docker daemon itself starts on boot.
- No backup automation for world saves - back up your bind-mounted `data/`
  directory yourself.
- The bridge-vs-host networking question above hasn't been re-tested since
  it was first hit - if you get bridge networking working reliably, please
  open an issue/PR.
